# Iso Tycoon – браузерный бизнес-симулятор (MVP «Кофейня»)

Идея: максимально реалистичный бизнес-симулятор для Steam. Игрок сразу директор.
Фишка – реалистичные правила: проверки (СЭС, пожарная, трудовая, налоговая),
налоги, кредиты, персонал (официально или «в конверте»), конкуренты, события.
Проверки – главная механика, у игрока всегда есть ход (подготовка, оспорить, принять).
Страна вымышленная, законы реалистичные. В дальнейшем другие миры (доставка,
производство, агентство, банк) – каждый отдельный мир с нуля. Сейчас только кофейня.

MVP: одна кофейня, один игровой год (360 дней, месяц = 30 дней), 3 уровня
сложности (Учебка / Реализм / Выживание), цель – плейтест с друзьями на 3–5 человек.

Время: 24 секунды реального времени = 1 игровой день (1 с = 1 игровой час).
Скорости 1× / 2× / 3× / пауза, автопауза на событиях и проверках.
Значение dayLengthSec = 24 хранится в src/data/balance.json.

Стек: Vite + TypeScript (vanilla-ts), Vitest. Для Steam позже упаковка в
Electron/Tauri или перенос ядра в Unity/Godot. Графика: 2D-изометрия, плоский стиль,
дизайн-система Iso Tycoon (docs/design-system). 3D нет.

## Архитектура

- src/core/ – чистая логика без DOM и UI: GameState, simulateDay(state), модули
  Demand, Staff, Inventory, Taxes, Loans, Compliance, Inspections, Competitors,
  Reputation, Events. Ядро считает дни, а не секунды.
- src/data/ – все числа и тексты в JSON: balance.json, items.json, events.json,
  inspections.json, inspectors.json. Баланс правится без кода.
- src/ui/ – экраны на компонентах Iso Tycoon. UI только читает состояние и
  отправляет команды (SetPrice, Hire, TakeLoan, ChooseEventOption и т. д.).
- Вся случайность через один генератор с сидом. Сид + лог команд = точный повтор партии.
- Сохранение = состояние в JSON. Телеметрия: строка на каждый день и каждое решение.
- Режим разработчика включается адресом `?dev` (кнопка DEV или F2): деньги, репутация, погода, перемотка дней,
  запуск события или проверки, готовые сценарии из src/data/devScenarios.json. Без `?dev` отладки нет.
- Три слота сохранений в главном меню. Подробности – docs/GUIDE.md, состояние игры – docs/REPORT.md.

## Дизайн-система

Лежит в docs/design-system/: tokens.json (источник), tokens.css (переменные, темы
день/ночь через атрибут data-theme="night"), bundle.css (компоненты it-*),
bundle.js (глобальный IsoTycoon.render / IsoTycoon.thumb для изометрической карты),
README.md (принципы), examples/GameScreen.html (рабочий пример основного экрана).
При создании каркаса перенеси их в src/ui/ и оформи bundle.js как TypeScript-модуль.

## Правила работы

- Ядро покрываем тестами Vitest, пишем скрипт, который прогоняет 1 000 партий
  ботами («честный», «серый», «кредитный агрессор») для проверки баланса.
- Цифры в docs/PLAN.md – стартовые, правим по результатам симуляции и плейтеста.
- Во всех текстах и документах используй среднее тире (–), не длинное (—).

Полный план механик, формул, проверок, кредитов, экранов и этапов – docs/PLAN.md.

## Первая задача

Создать каркас проекта (Vite vanilla-ts, папки core/data/ui, Vitest),
реализовать игровые часы (24 с = 1 день, пауза, 1×/2×/3×) и простейший simulateDay
с продажами по формуле спроса из плана, с тестами. Дальше по слоям: персонал и
склад, налоги, кредиты, проверки, события, конкуренты. Остановись после каркаса и
покажи, как запустить.
